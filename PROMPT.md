# Prompt: build "Dev break" (human-in-the-loop) from scratch

Give this whole file to a coding agent. It describes the complete app; build it, run it, and verify every feature.

---

Build **Dev break**, a Windows tray app that gives a developer a short brain break from working with AI: once an hour
it pops up a computer-science / architecture question generated by the `claude` CLI, lets them answer, scores the
answer, shows a model answer, and lets them discuss it in a chat. The same window has a **learn path**: a course per
topic, written by Claude, from the theory to what every senior engineer should know, with real examples.

## Tech

- C# WPF on .NET 10 (`net10.0-windows`), `UseWPF` + `UseWindowsForms` (WinForms only for the tray `NotifyIcon`).
  Nullable enabled, implicit usings off, `NoWarn WPF0001`. Assembly/namespace `DevBreak`.
- `App.xaml`: `ThemeMode="System"` (Fluent theme, follows light/dark), `ShutdownMode="OnExplicitShutdown"`.
  Use `AccentButtonStyle` for the main button.
- No NuGet packages. No database. Everything AI goes through the user's own logged-in `claude` CLI.
- `profile.txt`: `<None Update="profile.txt" CopyToOutputDirectory="PreserveNewest" ExcludeFromSingleFile="true" />`.
- Single-file publish: `dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o publish`.
- `.gitignore`: `bin/ obj/ publish/ *.user .vs/ profile.txt .claude/ learn/`. MIT license.

## Calling Claude (`QuestionGenerator.RunClaudeAsync`)

Start `claude` as a child process with arguments (use `ArgumentList`):
`-p --tools "" --strict-mcp-config --setting-sources "" --no-session-persistence`
- Working directory: the temp folder. No window. Write the prompt to **stdin** as UTF-8 without BOM, then close stdin.
  Read stdout/stderr as UTF-8. Timeout 3 minutes. Non-zero exit → exception with stdout + stderr.
- Do NOT use `--bare` (it fails with "Not logged in").

## Levels (by time of day)

`record Level(Name, Style, Topics)`; `Level.At(time)`: before 12:00 Heavy, 12:00-15:00 Medium, after 15:00 Light.
- **Heavy**: "an architecture / system-design decision with real trade-offs (2-4 options to choose between)".
  Topics: distributed systems, caching strategy, database design and scaling, consistency and transactions, messaging
  and event-driven design, API design, microservices vs monolith, security architecture, observability and reliability,
  cloud cost and scaling, data pipelines.
- **Medium**: "a focused technical question that needs some reasoning". Topics: algorithms and complexity, data
  structures, concurrency, SQL and indexes, JVM internals, networking and HTTP, operating systems, Spring and JPA,
  testing strategy, design patterns.
- **Light**: "a quick question answerable in under a minute (a short snippet, a definition, a "what does this print")".
  Topics: Java language trivia, git, HTTP status codes, Linux / shell commands, regex, JavaScript quirks, SQL
  basics, CS history, computer architecture basics, encoding and Unicode.

## Tabs (categories) - one per part of the developer's service stack

`record Category(Name, Topics)`; `TopicsFor(level)` returns its own topics, or the level's topics when it has none.
- **Mix**: no topics (uses the level's list).
- **Architecture**: distributed systems, caching strategy, messaging and event-driven design, consistency and
  transactions, API design, microservices vs monolith, resilience (retries, timeouts, circuit breakers), scaling a
  search-heavy system.
- **GCP**: Cloud Run scaling and cold starts, Cloud SQL and connections, IAM and service accounts, load balancers, Cloud
  Armor and IAP, Pub/Sub, Cloud Logging and Cloud Trace, Cloud Build and Cloud Deploy, GCP cost, Terraform on GCP,
  Vertex AI.
- **Java & Spring**: JVM memory and GC, concurrency and java.util.concurrent, virtual threads, Spring Boot internals
  (auto-configuration, proxies), Spring transactions, JPA / Hibernate, Java language features (records, sealed types,
  pattern matching, streams), Spring Security.
- **PostgreSQL**: indexes and query plans (EXPLAIN), MVCC and VACUUM, locking and isolation levels, partitioning, JSONB,
  connection pooling, Cloud SQL for PostgreSQL.
- **Oracle**: execution plans and the optimizer, indexes, PL/SQL, sequences and identity columns, read consistency,
  undo and locking, partitioning, Oracle vs PostgreSQL differences, Oracle on OCI.
- **Redis**: Redis data structures, caching patterns (cache-aside, write-through), expiry and eviction, persistence
  (RDB, AOF), Redis with Spring, distributed locks, pub/sub and streams.
- **Algorithms**: algorithms and complexity, data structures, graphs and shortest paths, sorting and searching, dynamic
  programming, hashing.
- **Browser & Next.js**: cookies vs localStorage vs sessionStorage, browser and HTTP caching, CORS and the same-origin
  policy, the JavaScript event loop, Next.js rendering (SSR, SSG, RSC), React state and effects, TypeScript types, web
  performance (Core Web Vitals).
- **DevOps**: Docker, Terraform, Bitbucket Pipelines CI/CD, git, observability (logs, metrics, traces), deployments and
  rollbacks (Cloud Run revisions).

The tabs name technologies only (no company or personal data). Personalisation of the questions themselves comes from
"Knowledge" below.

## Knowledge about the user (`Knowledge.cs`)

`enum KnowledgeSource { None, File, Claude }`, saved as `{"knowledge":"File"}` in `settings.json` next to the exe
(default `File` when missing). `Knowledge.GetAsync()` returns the text that goes into the question prompt:
- **File**: `profile.txt` next to the exe (empty if missing). The user writes a few lines about their role and stack.
- **Claude**: a summary of the user's own Claude Code history, built **once a day** and cached in
  `knowledge-from-claude.txt` next to the exe (reuse it if its write date is today; share one in-flight Task so
  parallel question generation builds it once; rebuild if that Task faulted).
  - Read `%USERPROFILE%\.claude\projects\<project-folder>\*.jsonl` files written in the last 7 days
    (open with `FileShare.ReadWrite`; they may be in use).
  - Each line is JSON. Keep only prompts the user typed: `type == "user"`, `origin.kind == "human"`,
    `message.content` is a **string**, `timestamp` within 7 days. Skip unparsable lines.
  - Take the newest 200, newlines flattened, each cut to 300 characters; plus the names of project folders that had
    sessions in that window.
  - Prompt: "Below are a developer's own recent prompts to an AI coding assistant (last 7 days) and the names of the
    project folders they worked in. Describe this developer for a quiz app that sets questions in their world: their
    role, languages, frameworks, databases, cloud and tools, the kind of product they build, and what they worked on
    lately. Under 150 words, plain text. Leave out secrets, credentials, people's names, customer data and anything
    else private." followed by `PROJECT FOLDERS:` and `PROMPTS (newest first):`.
- **None**: empty.

## Generating a question (`GenerateAsync(level, topic)`)

Prompt (the "About this developer" block only when the knowledge is non-empty):
```
You are quizzing a developer during a short break.
About this developer:
<knowledge>

Where it fits naturally, set the question in their stack and domain, but keep it a general lesson that is worth knowing.

Write ONE <level> question about: <topic>.
Style: <level style>.
Keep the question under 120 words. Use plain text: no markdown headings, no bold, no lists markup.
Put every code snippet in a fenced block with its language, e.g. ```java, ```sql, ```javascript, ```bash.
Short names inside a sentence go in single backticks, e.g. `HashMap`.
Then give the background theory: the concepts someone needs to know to work it out, as a hint
(under 120 words). It must not give away the answer.
Then give the answer: the key insight first, then a short explanation (under 150 words).
For a design question there may be no single right answer: give the best choice and its trade-offs.

Reply in exactly this format and nothing else:
QUESTION:
<the question>
THEORY:
<the background theory>
ANSWER:
<the answer>
```
Parse by the `QUESTION:` / `THEORY:` / `ANSWER:` markers (in that order) into `record Question(Text, Theory, Answer)`; wrong format → exception with the
raw output.

## Scoring (`ScoreAsync(question, mine)`)

Prompt: grade fairly and encouragingly but honestly (credit the key insight even if worded loosely, take points for
wrong or missing key ideas), with QUESTION, REFERENCE ANSWER, THE DEVELOPER'S ANSWER; score 0-10 and under 60 words of
feedback, plain text. Reply format `SCORE: <0-10>` then `FEEDBACK:` + text. Parse with regex `SCORE:\s*(\d+)`, clamp
0-10 → `record Score(Points, Feedback)`.

## Discuss chat (`ChatAsync(question, mine, history)`)

The CLI keeps no session, so every turn sends everything: a friendly senior-engineer tutor persona ("answer their
latest message directly and concisely, usually under 150 words; go deeper, give examples, or correct them; plain text;
code in fenced blocks with the language"), QUESTION, REFERENCE ANSWER, THE DEVELOPER'S OWN ANSWER (or "(none)"), and
the conversation as `DEVELOPER: ...` / `TUTOR: ...` lines; "Reply with your answer only, without a "TUTOR:" prefix."

## Ready queue (`QuestionPool`)

So questions appear instantly:
- `record PendingQuestion(Topic, Task<Question>)`. Keep **2** ready per (tab, level).
- `Take(category, level)`: dequeue if available, otherwise start one the user waits for directly; then refill.
- `FillAll(level)`: top up every tab for that level. Background generation runs at most **3 at a time**
  (`SemaphoreSlim`); a question the user is waiting for skips that limit. A random topic from `TopicsFor(level)`.
- UI thread only.

## Learn path (`LearnPath.cs`)

A course per tab, every tab except Mix. All of it is written by Claude and cached under `learn\` next to the exe
(one folder per tab, name with non-alphanumerics replaced by `-`). One in-flight Task per course / lesson; a faulted
one is retried on the next request. UI thread only.
- `record Lesson(Title, Summary)`. **Syllabus** (`learn\<tab>\syllabus.json`), written once per tab. Prompt: "You are
  designing a short course for a developer who wants to master: <tab>. It covers what every senior software engineer
  working with <tab> should know: the theory behind it and the important, practical things that matter in real systems.
  Scope (use as a guide): <the tab's topics>." + the knowledge block ("About the learner:") when non-empty + "Write
  exactly 12 lessons, ordered from the foundations to senior-level topics. Each lesson is one focused subject, e.g. for
  a browser course "cookies vs localStorage vs sessionStorage"." Reply format, one per line:
  `1. <title> | <one-sentence summary>`. Parse lines that start with a number, a dot and have a `|`.
- `record LessonContent(Text, Check, Answer)`. **Lesson** (`learn\<tab>\lesson-NN.json`), written when first opened.
  Prompt: "You are teaching lesson N of a <tab> course for developers growing into senior engineers." + knowledge
  block + the numbered course list + "This lesson: <title> - <summary>" + "Teach it in under 600 words: the theory: what
  it is, how it works underneath, and why it is designed that way; real examples where they apply (real code, commands,
  configuration or a realistic production scenario); what a senior engineer must know: trade-offs, common mistakes and
  pitfalls. Plain text with short paragraphs; you may use simple "- " bullets. No markdown headings and no bold." + the
  fenced-code / backtick rules + "Then write one short question that checks the key idea of the lesson, and its answer
  (under 80 words)." Reply format `LESSON:` / `CHECK:` / `ANSWER:`.
- **Progress**: `learn\progress.json`, `{ "<tab>": [done lesson indexes] }`.

## Tray app (`App.xaml.cs`)

- `--now` argument: open one question window, exit when it closes (`OnLastWindowClose`). No tray.
- Otherwise a `NotifyIcon` with a drawn icon (green circle, white bold "?"), tooltip "Dev break - a question at :55
  every hour". Left-click → ask now. Context menu: "Ask me now", "Learn path" (opens the window on the learn path), "Knowledge about me" submenu (From my Claude history
  (summary once a day) / From profile.txt / None (generic questions), checkable, synced with the window's dropdown
  when opened), separator, "Exit".
- On start `FillAll(Level.At(now))`. A `DispatcherTimer` every 20 s: `FillAll` for the current level; snooze handling
  (when the snooze time passes, ask); at minute **>= 55** once per hour, show a balloon tip "Time for a 5-minute brain
  break." and open the window.
- Only one question window at a time (activate the open one). Snooze = 15 minutes.

## Main window (`QuestionWindow`): Quiz and Learn path in one window

At the top, two toggle buttons in one group (`RadioButton`s with the `ToggleButton` style): **Quiz** (default) and
**Learn path**. They swap the whole content below between the quiz view and the learn view (`LearnView`, a
`UserControl`). Switching to Learn path grows the window once to 1180x820 (capped to the work area, placed
bottom-right; never shrinks), sets the title "Dev break - learn path", and opens the first course only then (a quiz
popup never writes a course). Switching back shows the quiz tab again.

### Quiz view

900x680, min 560x460, Topmost, placed bottom-right of the work area (16 px margin). Rows:
1. A `TabControl` with one header per category (headers only; the content area below is shared). Each tab keeps its
   own state: level, pending question, question, error, typed answer, answer shown, scoring, score, score error, chat
   window. Selecting a tab with no state starts a question.
2. Header: a rounded level badge (Heavy red `#C62828`, Medium orange `#EF6C00`, Light green `#2E7D32`) and the topic
   (18 pt semibold). On the right: "Knowledge about me" ComboBox (From my Claude history / From profile.txt / None
   (generic); changing it saves the setting) and "Level for new questions" ComboBox (Auto (now: X) / Heavy / Medium /
   Light).
3. The question in a read-only `RichTextBox` (rendered by `CodeRenderer`), with a loading overlay (indeterminate
   progress bar + "Generating a <level> question about <topic>...") while it generates; errors shown in its place.
4. An `Expander` "Hint: background theory", **closed** by default, with the question's theory in a read-only
   `RichTextBox` (rendered by `CodeRenderer`, max 200 px high, scrolls). Disabled until the question is ready. Each tab
   remembers whether its hint is open; a new question starts closed. Below it, "Your answer (optional)" multi-line
   TextBox, 64 px high.
5. Answer panel, hidden until revealed: "Answer" + score badge ("Your score N/10": green >= 8, orange >= 5, red below)
   or a small progress bar + "Scoring your answer...", the feedback text, and the model answer in a `RichTextBox`.
   When revealed the window grows to the full work-area height so question and answer fit without scrolling, and the
   answer box becomes read-only.
6. Buttons (right-aligned): **Discuss** (enabled once the answer is shown), **Next question**, **Snooze 15 min**,
   **Skip** (close), **Show answer**, **Check my answer** (accent; enabled only when the answer box has text; reveals
   and scores).
Async results only update the UI if that tab and that state are still current. Window title:
"Dev break - <tab> - <level> - <topic>".

### Learn view (`LearnView`)

Its own `TabControl` (headers only) with one tab per course. Below, two columns:
- **Left (320 px)**: "N of 12 lessons done", then a `ListBox` of lessons: "✓  N. <title>" (an em space instead of ✓
  when not done), titles wrap (no horizontal scroll), the summary as tooltip. Opening a course selects the first lesson
  not done yet.
- **Right**: the lesson title (18 pt semibold, "N. <title>") and summary (dimmed); the lesson in a read-only
  `RichTextBox` (rendered by `CodeRenderer`) with a loading overlay ("Writing the <tab> course..." / "Writing lesson N:
  <title>..."; errors shown in its place); below it "Check yourself" with the check question in a `RichTextBox` (max
  140 px) and an `Expander` "Answer", closed for every lesson; buttons **Previous**, **Mark as done** (toggles; shows
  "Done ✓ (undo)" when done), **Next lesson** (accent).
- A version counter drops a slow reply for a tab or lesson that is no longer selected. Do NOT name a control
  `CheckBox` (it hides WPF's `CheckBox`).

## Chat window (`ChatWindow`)

760x760, Topmost, placed to the left of the question window. One per tab state (Discuss again re-activates it).
Title "Discuss: <topic>", a read-only transcript `RichTextBox` with "You" (SteelBlue) / "Claude" (SeaGreen) labels and
messages rendered by `CodeRenderer.Append`, a first Claude message "Ask anything about this question or its answer:
why, what if, a deeper example, or check an idea.", an input box (Enter sends, Shift+Enter new line; do NOT name it
`MessageBox`, it hides WPF's `MessageBox`), a Send button (accent), and "Claude is thinking..." while waiting. On error
show it and drop the unanswered message from history.

## Code rendering (`CodeRenderer`)

`Render(text)` → `FlowDocument` (Segoe UI, left aligned, not justified); `Append(document, text)` for the chat.
- Fenced blocks ```` ```lang ```` → a dark box (`#1E1E1E`, Cascadia Mono / Consolas) coloured like VS Code Dark+:
  keywords `#569CD6`, strings `#CE9178`, comments `#6A9955`, numbers `#B5CEA8`, types (PascalCase) `#4EC9B0`, functions
  (word before `(`) `#DCDCAA`, plain `#D4D4D4`. Token regexes for C-like languages (java, js/ts, c#, kotlin...),
  SQL (case-insensitive keywords, `--` comments) and hash-comment languages (bash, python, yaml...).
- Inline `` `code` `` → code font in `#C7254E`. Everything else plain text.
