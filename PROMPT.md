# Prompt: build "Dev break" (human-in-the-loop) from scratch

Give this whole file to a coding agent. It describes the complete app; build it, run it, and verify every feature.

---

Build **Dev break**, a Windows tray app that gives a developer a short brain break from working with AI: once an hour
it pops up a computer-science / architecture question generated by the `claude` CLI, lets them answer, scores the
answer, shows a model answer, and lets them discuss it with Claude in a side panel. The same window has a **learn
path**: a course per topic, written by Claude, from the theory to what every senior engineer should know, with real
examples; and a daily **TL;DR** per topic, written from the web, every item explained for the developer's own stack,
which they can save into their own Claude Code memory or skills. Discussions may look at the developer's machine,
read-only. It is
**gamified**: XP and ranks, a daily streak and goal, badges, and a stats screen; weak topics are asked more often.
The look is light and simple: a compact card, topic chips, three buttons, settings behind a gear.

## Tech

- C# WPF on .NET 10 (`net10.0-windows`), `UseWPF` + `UseWindowsForms` (WinForms only for the tray `NotifyIcon`).
  Nullable enabled, implicit usings off, `NoWarn WPF0001`. Assembly/namespace `DevBreak`.
- `App.xaml`: `ThemeMode="System"` (Fluent theme, follows light/dark), `ShutdownMode="OnExplicitShutdown"`.
  Use `AccentButtonStyle` for the main button.
- No NuGet packages. No database. Everything AI goes through the user's own logged-in `claude` CLI.
- `profile.txt`: `<None Update="profile.txt" CopyToOutputDirectory="PreserveNewest" ExcludeFromSingleFile="true" />`.
- Single-file publish: `dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o publish`.
- `.gitignore`: `bin/ obj/ publish/ *.user .vs/ profile.txt .claude/ learn/ game.json topics.json`. MIT license.

## Calling Claude (`QuestionGenerator.RunClaudeAsync`)

Start `claude` as a child process with arguments (use `ArgumentList`):
`-p --tools "" --strict-mcp-config --setting-sources "" --no-session-persistence`
- Working directory: the temp folder. No window. Write the prompt to **stdin** as UTF-8 without BOM, then close stdin.
  Read stdout/stderr as UTF-8. Timeout 3 minutes. Non-zero exit → exception with stdout + stderr. On timeout kill the
  whole process tree. Start the process off the UI thread (`claude.exe` is large and takes ~0.5 s to start).
- Do NOT use `--bare` (it fails with "Not logged in").
- `RunClaudeAsync(prompt, web: true)` (only the TL;DR): the same with `--tools "WebSearch,WebFetch" --allowedTools
  "WebSearch,WebFetch"` instead of `--tools ""` (allowed up front, because `-p` cannot ask).
- Discussions use their own run, see **Discussions** below.

## Levels (by time of day)

`record Level(Name, Style, Topics)`; `Level.At(time)`: before 12:00 Heavy, 12:00-15:00 Medium, after 15:00 Light.
- **Heavy**: "an architecture / system-design decision with real trade-offs (2-4 options to choose between)".
  Topics: distributed systems, caching strategy, database design and scaling, consistency and transactions, messaging
  and event-driven design, API design, microservices vs monolith, security architecture, observability and reliability,
  cloud cost and scaling, data pipelines.
- **Medium**: "a focused technical question that needs some reasoning". Topics: algorithms and complexity, data
  structures, concurrency, SQL and indexes, JVM internals, networking and HTTP, operating systems, Spring and JPA,
  testing strategy, design patterns.
- **Light**: "a quick question answerable in under a minute (a short snippet, a definition, a "what does this print")".
  Topics: Java language trivia, git, HTTP status codes, Linux / shell commands, regex, JavaScript quirks, SQL
  basics, CS history, computer architecture basics, encoding and Unicode.

## Tabs (categories) - the user's own topics (`Topics.cs`)

`record Category(Name, Topics)`; `TopicsFor(level)` returns its own topics, or the level's topics when it has none.
`Category.All` = **Mix** (no topics; uses the level's list) followed by the user's chosen topics. Nothing is
hard-coded: the topics are saved as `[{"Name":..., "Topics":[...]}]` in `topics.json` next to the exe (git-ignored).
`Topics.IsSetUp` = that file exists. `Topics.Save(chosen)` writes it, keeps the existing `Category` instances for
unchanged topics (open tabs and queued questions stay attached) and raises `Topics.Changed`.

- **`SuggestAsync()`**: read the user's typed Claude Code prompts exactly as for "Knowledge" below
  (`Knowledge.RecentPrompts()`: last 7 days, newest 200). No prompts → return an empty list without calling Claude.
  Otherwise prompt: "Below are a developer's own recent prompts to an AI coding assistant and the names of the project
  folders they worked in. Suggest up to 10 topics this developer would gain from learning more about, based on the
  technologies and engineering problems they work with." + "Only general, public high-tech topics (software, data,
  cloud, AI, security, networks, hardware, engineering practice). Never anything personal or private: no health,
  family, money or personal life, nothing about the user's employer, company, customers, products or business, no
  people's names, no internal project names." + "Each topic is a short tab name (1-3 words, e.g. "PostgreSQL",
  "Kubernetes", "System design") with 4-8 sub-topics." Reply one per line: `<tab name> | <sub>; <sub>; <sub>`,
  followed by `PROJECT FOLDERS:` and `PROMPTS (newest first):`.
- **`ShapeAsync(wish)`**: what the user typed ("I want to learn business regulation on PII") → prompt: "A developer
  typed what they want to learn in a quiz and course app: "<wish>". Turn it into one topic: a short tab name (1-4
  words) and 4-8 sub-topics that cover it from the basics to what a senior professional should know." Same one-line
  reply format. The no-personal rule applies only to suggestions: a topic the user asks for is theirs.
- Parsing: lines with `|`; name trimmed of `-`/`*` bullets; sub-topics split on `;`; skip empty, "Mix" and duplicate
  names (case-insensitive); no topics at all → exception with the reply.

### Topics window (`TopicsWindow`)

720x680, Topmost, centred. "What do you want to learn?" (20 pt semibold) and an intro line; a card with one
`CheckBox` per topic (name semibold, sub-topics comma-separated below, small and faded); "Add a topic of your own": a
`TextBox` + "Add with AI" button (enabled when text is typed; Enter also adds) and a hint "e.g. "I want to learn
business regulation on PII" - Claude turns it into a topic"; Cancel and Save (accent) at the bottom.
- **First run** (`isFirstRun`): intro "Suggested from your own Claude Code chats of the last 7 days - general tech
  topics only, nothing personal. Tick the ones you want, or add your own below."; a loading overlay "Reading your
  Claude chats to suggest topics..." while `SuggestAsync` runs; suggestions start **unticked**. No chats → "No Claude
  Code chats found yet, so there is nothing to suggest. Add the topics you want below."; an error is shown in the card.
- **From the gear menu**: intro "Untick a topic to remove its tab, or add a new one below."; the current topics, ticked.
- Add with AI: disable the box, hint "Claude is shaping your topic...", then add the topic **ticked** (replacing a
  row with the same name), clear the box, hint 'Added "<name>". Add another, or Save.'; on error the hint shows it.
- Save: `Topics.Save(ticked rows in order)`, close with `DialogResult = true`. Cancel changes nothing.

## Knowledge about the user (`Knowledge.cs`)

`enum KnowledgeSource { None, File, Claude }`, saved as `"knowledge":"File"` in `settings.json` next to the exe
(default `File` when missing). `settings.json` is a flat string map shared by every setting (`AppSettings.Get/Set`;
writing one key keeps the others; an unreadable file reads as empty). `Knowledge.GetAsync()` returns the text that goes
into the question, lesson, TL;DR and discussion prompts (`LearnPath.AboutThemAsync()` wraps it as "About the learner:"):
- **File**: `profile.txt` next to the exe (empty if missing). The user writes a few lines about their role and stack.
- **Claude**: a summary of the user's own Claude Code history, built **once a day** and cached in
  `knowledge-from-claude.txt` next to the exe (reuse it if its write date is today; share one in-flight Task so
  parallel question generation builds it once; rebuild if that Task faulted).
  - `Knowledge.RecentPrompts()` (shared with topic suggestions): read
    `%USERPROFILE%\.claude\projects\<project-folder>\*.jsonl` files written in the last 7 days
    (open with `FileShare.ReadWrite`; they may be in use).
  - Each line is JSON. Keep only prompts the user typed: `type == "user"`, `origin.kind == "human"`,
    `message.content` is a **string**, `timestamp` within 7 days. Skip unparsable lines.
  - Take the newest 200, newlines flattened, each cut to 300 characters; plus the names of project folders that had
    sessions in that window.
  - Prompt: "Below are a developer's own recent prompts to an AI coding assistant (last 7 days) and the names of the
    project folders they worked in. Describe this developer for a quiz app that sets questions in their world: their
    role, languages, frameworks, databases, cloud and tools, the kind of product they build, and what they worked on
    lately. Under 150 words, plain text. Leave out secrets, credentials, people's names, customer data and anything
    else private." followed by `PROJECT FOLDERS:` and `PROMPTS (newest first):`.
- **None**: empty.

## Generating a question (`GenerateAsync(level, topic)`)

Prompt (the "About this developer" block only when the knowledge is non-empty):
```
You are quizzing a developer during a short break.
About this developer:
<knowledge>

Where it fits naturally, set the question in their stack and domain, but keep it a general lesson that is worth knowing.

Write ONE <level> question about: <topic>.
Style: <level style>.
Keep the question under 120 words. Use plain text: no markdown headings, no bold, no lists markup.
Put every code snippet in a fenced block with its language, e.g. ```java, ```sql, ```javascript, ```bash.
Short names inside a sentence go in single backticks, e.g. `HashMap`.
Then give the background theory: the concepts someone needs to know to work it out, as a hint
(under 120 words). It must not give away the answer.
Then give the answer: the key insight first, then a short explanation (under 150 words).
For a design question there may be no single right answer: give the best choice and its trade-offs.

Reply in exactly this format and nothing else:
QUESTION:
<the question>
THEORY:
<the background theory>
ANSWER:
<the answer>
```
Parse by the `QUESTION:` / `THEORY:` / `ANSWER:` markers (in that order) into `record Question(Text, Theory, Answer)`; wrong format → exception with the
raw output.

## Scoring (`ScoreAsync(question, mine)`)

Prompt: grade fairly and encouragingly but honestly (credit the key insight even if worded loosely, take points for
wrong or missing key ideas), with QUESTION, REFERENCE ANSWER, THE DEVELOPER'S ANSWER; score 0-10 and under 60 words of
feedback, plain text. Reply format `SCORE: <0-10>` then `FEEDBACK:` + text. Parse with regex `SCORE:\s*(\d+)`, clamp
0-10 → `record Score(Points, Feedback)`.

## Discussions (`ChatAsync`, `ChatAboutLessonAsync`, `ChatAboutTldrAsync`)

Three kinds, one shape. The CLI keeps no session, so every turn sends everything, split in two:
- **System prompt** (the context): a friendly senior-engineer tutor persona; the shared rules ("answer their latest
  message directly and concisely, usually under 150 words; go deeper, give examples, or correct them; when they ask
  what it means for their own work, products or platform, answer in terms of what is known about them; format lightly,
  it is rendered: short paragraphs, "- " or "1. " lists, **bold** for the key point, no headings and no tables; code in
  fenced blocks with the language, short names in backticks; when the developer attached images, read each one with
  the Read tool before answering"); the knowledge block;
  the machine notes (below); then the item:
  - **quiz**: QUESTION, REFERENCE ANSWER, THE DEVELOPER'S OWN ANSWER (or "(none)") and ITS SCORE ("N/10 - feedback" or
    "(not checked yet)"). Answer and score are read at **every turn**, so a check done after the chat opened is known.
  - **lesson**: THE LESSON (title - summary, then its text), ITS CHECK QUESTION, ITS ANSWER.
  - **TL;DR**: the whole TL;DR as text (each section title in caps with its items, then SOURCES), with its date; also
    "when it is about something recent, search the web and fetch the official source first, and name the page with its
    full https URL".
- **User turn**: "CONVERSATION SO FAR (the last DEVELOPER message is the one to answer):" + `DEVELOPER: ...` /
  `TUTOR: ...` lines + "Reply with your answer only, without a "TUTOR:" prefix."

**Run** (`RunDiscussionAsync(system, prompt)`): the developer may let Claude look at their machine, **read-only**:
- Their projects: `ClaudeProjects.Find()` (see **Save it to my Claude**) and the git repos in them
  (`ClaudeProjects.GitRepos()`: a project folder with `.git`, or a folder up to two levels below one; skip `.`-folders,
  `node_modules`, `build`, `bin`, `obj`; at most 100).
- Arguments: `-p --tools "Read,Grep,Glob,WebSearch,WebFetch,PowerShell" --settings <file>
  --disallowedTools "Write,Edit,NotebookEdit" --append-system-prompt-file <file> --no-session-persistence`, plus
  `--add-dir <folder>` for every project folder; with the **Clean** setup also `--setting-sources "" --strict-mcp-config`.
  No permission bypass: `-p` cannot ask, so anything not allowed is denied.
- The `--settings` file holds `permissions.allow`: `Read`, `Grep`, `Glob`, `WebSearch`, `WebFetch`, `PowerShell(dir:*)`,
  and per repo `PowerShell(git -C <repo> log|status|diff|show:*)` and, when it has `gradlew.bat`,
  `PowerShell(<repo>\gradlew.bat -p <repo> dependencies|dependencyInsight:*)` (also without `.bat`); `permissions.deny`:
  Write, Edit, NotebookEdit. Why per repo: `git -C <path>` and `gradlew -p <path>` take any subcommand, and Claude Code
  always asks before `cd ...; <command>`. Dozens of repos overflow a command line, hence a file.
- The system prompt also goes in a file (a TL;DR is too long for a command line). Both files are named per turn (two
  discussions can run at once) and deleted when the turn ends. Working directory: the temp folder. Timeout **10
  minutes** (a dependency report can be slow).
- Machine notes in the system prompt: "You run on the developer's own machine and may look at it, read-only: read and
  search files in their Claude Code project folders, search the web, and run only these commands -" the git form
  "exactly as: git -C <repo path as listed below> log|status|diff|show ... (never cd + git, never another subcommand)",
  `dir`, and "a Gradle dependency report, exactly as: <repo>\gradlew.bat -p <repo> dependencies|dependencyInsight ...
  (never cd first)"; "When an answer depends on their actual code, versions or setup, check it yourself instead of
  guessing or asking them to run something, and say in one line what you looked at. You cannot change anything."; then
  the project folders and the git repos, one per line.
- **Setup** (`enum ClaudeSetup { Clean, Mine }`, `"discussSetup"` in `settings.json`, default Clean): Clean leaves out
  the user's own Claude settings, hooks and MCP servers; Mine loads them like their CLI (slower).

## Ready queue (`QuestionPool`)

So questions appear instantly:
- `record PendingQuestion(Topic, Task<Question>)`. Keep **2** ready per (tab, level).
- `Take(category, level)`: dequeue if available, otherwise start one the user waits for directly; then refill.
- `FillAll(level)`: top up every tab for that level. Background generation runs at most **3 at a time**
  (`SemaphoreSlim`); a question the user is waiting for skips that limit. A random topic from `TopicsFor(level)`.
- UI thread only.

## Learn path (`LearnPath.cs`)

A course per tab, every tab except Mix. All of it is written by Claude and cached under `learn\` next to the exe
(one folder per tab, name with non-alphanumerics replaced by `-`). One in-flight Task per course / lesson; a faulted
one is retried on the next request. UI thread only.
- `record Lesson(Title, Summary)`. **Syllabus** (`learn\<tab>\syllabus.json`), written once per tab. Prompt: "You are
  designing a short course for a developer who wants to master: <tab>. It covers what every senior software engineer
  working with <tab> should know: the theory behind it and the important, practical things that matter in real systems.
  Scope (use as a guide): <the tab's topics>." + the knowledge block ("About the learner:") when non-empty + "Write
  exactly 12 lessons, ordered from the foundations to senior-level topics. Each lesson is one focused subject, e.g. for
  a browser course "cookies vs localStorage vs sessionStorage"." Reply format, one per line:
  `1. <title> | <one-sentence summary>`. Parse lines that start with a number, a dot and have a `|`.
- `record LessonContent(Text, Check, Answer)`. **Lesson** (`learn\<tab>\lesson-NN.json`), written when first opened.
  Prompt: "You are teaching lesson N of a <tab> course for developers growing into senior engineers." + knowledge
  block + the numbered course list + "This lesson: <title> - <summary>" + "Teach it in under 600 words: the theory: what
  it is, how it works underneath, and why it is designed that way; real examples where they apply (real code, commands,
  configuration or a realistic production scenario); what a senior engineer must know: trade-offs, common mistakes and
  pitfalls. Plain text with short paragraphs; you may use simple "- " bullets. No markdown headings and no bold." + the
  fenced-code / backtick rules + "Then write one short question that checks the key idea of the lesson, and its answer
  (under 80 words)." Reply format `LESSON:` / `CHECK:` / `ANSWER:`.
- **Progress**: `learn\progress.json`, `{ "<tab>": [done lesson indexes] }`.
- **Prepared ahead** so opening a course or carrying on is instant: `PrepareAll()` on tray start writes every course's
  lesson list and its next lesson not done yet (already written ones are read from disk); `PrepareAsync(tab)` runs
  again after **Mark as done** to get the next lesson ready. At most **3** courses prepare at a time (`SemaphoreSlim`);
  failures are swallowed there and shown/retried when the user opens that course or lesson.

## TL;DR (`Tldr.cs`)

A daily briefing per tab (every tab except Mix), written by Claude **from the web** (`RunClaudeAsync(prompt, web:
true)`), cached as `tldr\<tab>.json` next to the exe (name with non-alphanumerics replaced by `-`). UI thread only;
one in-flight Task per tab, a faulted one is retried.
- `record TldrSection(Title, Text)`, `record TldrSource(Title, Url)`, `record TldrContent(Written, Sections, Sources?,
  Format = 0)` with `CurrentFormat = 2`. A saved TL;DR is **old** - written again - when it is a day old, has no sources
  or an older format. `GetAsync(tab, refresh)` reads it from disk while not old, else writes it.
- Prompt: "You are writing a TL;DR briefing on <tab> for a developer growing into a senior engineer. Scope (use as a
  guide): <topics>." + knowledge block + "Today is <yyyy-MM-dd>. First search the web and fetch the official sources
  (release notes, changelogs, official blogs and docs) to get the latest, current data. Do not rely on memory for
  anything recent, and give version numbers and dates." + five sections, 3 or 4 items each: LATEST RELEASES (headline
  with version and date), HOT TOPICS, INTERESTING QUIRKS, WHAT A SENIOR MUST KNOW, OPTIMIZATION TIPS. Every item, each
  line 1-3 sentences: `* <short headline>`, `Context:` (the background - the problem or the situation before), `Why:`
  (why they did it / why it works this way), `Good for:` (what it gives in practice, with a concrete example or
  snippet), `For you:` (what it means for the learner's own work and products; "Not directly relevant to your stack."
  when it does not apply - never invent a link; left out when nothing is known about the learner). Under 2000 words.
  Then `SOURCES:` every page used, one per line `- <page title> | <full https URL>`. Plain text, the code rules.
  Reply format: each title alone on its line with a colon, followed by its items, then SOURCES.
- Parse each section between its title and the next; any title missing → exception with the reply. Section titles are
  stored capitalized ("Latest releases"). Sources: keep only absolute http/https URLs (they open in the browser).
- `PrepareAll()`: every tab's TL;DR in the background, **2 at a time** (`SemaphoreSlim`), on tray start and on
  `Topics.Changed`; failures are left for when the tab is opened.

### TL;DR view (`TldrView`)

- Topic chips (`ChipList`) per tab; a header card: "fresh from the web" (hand note), the tab name, "UPDATED <date> ·
  N SOURCES", **Refresh** (rewrites now) and **Discuss** (enabled when a TL;DR is shown).
- **Sub-tabs** in the mode-tab style: Latest releases · Hot topics · Quirks · Senior must-know · Optimization ·
  Sources (N). The open sub-tab stays when another tab is picked.
- A section: a numbered eyebrow ("01 · LATEST RELEASES"), then per item a block with a coloured bar on the left (one
  accent per section), the headline (display font) with a small **+ my Claude** button after it, and its lines, each
  under a small mono label (CONTEXT, WHY, GOOD FOR); FOR YOU stands out on a violet tint. A section written without
  `* ` items is shown as it is. Sources: one line per page, a link (opens in the browser) and its host.
- Loading overlay "Claude is reading the latest on <tab> online..."; errors shown in its place. A version counter
  drops slow replies for a tab no longer selected. Opens its first tab only when the view is first shown.

## Save it to my Claude (`ClaudeProjects.cs`, `SharePanel`)

- **The user's projects**, found on the machine - nothing hard-coded: every folder in `%USERPROFILE%\.claude\projects`
  (or `DEVBREAK_CLAUDE_PROJECTS`, a sandbox for tests and demos); its real path is the `cwd` recorded in its newest
  session logs (`*.jsonl`, first 60 lines, opened with `FileShare.ReadWrite`); keep folders that exist, skip the temp
  folder and the home folder, no duplicates. A short **fingerprint** per folder: its first 24 top-level entries (not
  `.`-names) and the start of its `CLAUDE.md` or `README.md` (4 non-empty lines, 300 characters).
- **+ my Claude** on a TL;DR item opens the `SharePanel` beside the TL;DR (the same side panel as a discussion):
  "save it to your Claude" (hand note), the headline, a loading overlay "Claude is matching it to your projects...".
  `SuggestAsync(tab, item, sources)` (no tools): the item, the TL;DR's sources, the numbered projects with their
  fingerprints and the knowledge block; "Pick the projects this item is really useful for - at most 3, and none when it
  does not fit any of them. For each, choose: memory - a fact, change or gotcha Claude should remember when working in
  that project (most items); skill - only when the item is a procedure a developer would repeat there." Content for that
  project, with the source URL, today's date and a closing line to check it is still current; memory under 120 words,
  skill numbered steps under 300 words. Reply blocks `TARGET: <n> | <memory|skill> | <kebab-name> | <description>`,
  the content, `END` - or the single word `NONE`.
- Each suggestion: a ticked checkbox with a MEMORY / SKILL badge and the folder, "<name> - <description>", the content
  in an editable box. **Save selected** writes only the ticked ones; "Nothing is saved until you press Save." until then.
  - memory → `<projects>\<key>\memory\<name>.md` with front matter (`name`, `description`, `metadata: type:
    reference`) and the content, plus a line `- [<name>](<file>) — <description>` appended to that folder's `MEMORY.md`;
  - skill → `<project>\.claude\skills\<name>\SKILL.md` with front matter (`name`, `description`).
  Never overwrite: a taken name gets `-2`, `-3`... The status shows the saved paths.

## Sessions (`ClaudeSessions.cs`, `SessionsView`)

The user's own Claude Code, inside Dev break: real sessions - the same ones the CLI keeps under `.claude\projects` -
started in a folder or continued, worked in like the CLI, and continuable with `claude --resume <id>` in a terminal.
- **List**: every `<projects>\*\*.jsonl`, newest first, the first 60 whose folder (the first `cwd` in the file) still
  exists and is not under the temp folder. Title: the last `ai-title` / `custom-title` line (read from the last 256 KB),
  else the first prompt the user typed (`type == "user"`, string content, `origin.kind == "human"` or no origin, not
  starting with `<`), else the folder name. Read with `FileShare.ReadWrite | Delete` (sessions may be in use).
- **Transcript** of a session: its lines in order, skipping `isSidechain` and `isMeta`: the user's typed prompts, and
  each assistant message's `text` blocks and `tool_use` blocks (shown as a step: the tool name and its `command`,
  `file_path`, `pattern`, `url`, `query`, `description`, `prompt` or `skill`, 140 characters). The last 300 entries.
- **A turn** (`RunTurnAsync`): `claude -p --output-format stream-json --verbose --permission-mode bypassPermissions`
  and `--session-id <new id>` for a new session or `--resume <id>`, working directory = the session's folder, the
  message on stdin. No `--setting-sources`: the user's full setup loads (CLAUDE.md, memory, skills, plugins, hooks,
  MCP servers). Full access is the user's choice: `-p` cannot stop to ask. Each streamed `assistant` line adds its
  text and tool steps as they come; the `result` line adds "✓ done · <seconds> s · $<cost>" or its error. No timeout;
  **Stop** kills the process tree ("Stopped.").
- **View** (5th mode tab **Sessions**, wide): left a card "your Claude Code, here" / Sessions with **New session...**
  (a folder picker, `OpenFolderDialog`; the new session gets a fresh id and stays at the top of the list), **Refresh**,
  and the list (title, folder name · "N min/h/d ago", the folder as tooltip). Right: the title, "<folder> · session
  <id>", **Copy resume command** (`cd "<folder>"; claude --resume <id>`) and **Open folder**; the transcript (You /
  Claude rendered by `CodeRenderer` - formatting and diagrams -, tool steps in mono with a violet "⚙ <tool>", the done
  line, errors in coral); the input (Enter sends), Send, Stop, "Claude is working... (N steps)" and the note "Claude
  may edit files and run commands in this folder.". Every opened session keeps its transcript, and a running turn
  keeps going while another session is on screen. After a new session's first turn the list refreshes.

## Tray app (`App.xaml.cs`)

- **First run** (no `topics.json`): first check that Claude Code works by running the prompt "Reply with just: OK"
  through `RunClaudeAsync`. Not installed (`Win32Exception` starting `claude`) → error box "Claude Code is not
  installed. Install Claude Code, run "claude" once and log in, then start Dev break again."; any other failure → "Claude
  Code is installed but did not answer - is it logged in? Run "claude" once and log in, then start Dev break again." +
  the error; then exit. Otherwise show `TopicsWindow(isFirstRun: true)` as a dialog, then continue (the app runs with
  only Mix when the user cancels, and asks again next start).
- `Topics.Changed` → `FillAll(Level.At(now))`, `LearnPath.PrepareAll()` and `Tldr.PrepareAll()`.
- `--now` argument: open one question window, exit when it closes (`OnLastWindowClose`). No tray.
- Otherwise a `NotifyIcon` with a drawn icon (green circle, white bold "?"), tooltip "Dev break - a question at :55
  every hour". Left-click → ask now. Context menu: "Ask me now", "Learn path" (opens the window on the learn path), "Knowledge about me" submenu (From my Claude history
  (summary once a day) / From profile.txt / None (generic questions), checkable, synced with the window's dropdown
  when opened), separator, "Exit".
- On start `FillAll(Level.At(now))`, `LearnPath.PrepareAll()` and `Tldr.PrepareAll()`. A `DispatcherTimer` every 20 s: `FillAll` for the current level; snooze handling
  (when the snooze time passes, ask); at minute **>= 55** once per hour, show a balloon tip "Time for a 5-minute brain

## Game (`Game.cs`)

Local only, in `game.json` next to the exe: `Events` (`record GameEvent(At, Kind "question"|"lesson", Tab, Topic,
Score?, Xp, Lesson?)`), earned `Badges` (`record EarnedBadge(Id, At)`) and `GoalDays` (dates the daily goal was met).
- **XP**: a checked answer `10 + score*10` (10-110); Show answer without checking 5; a lesson marked done 50 (undo
  removes that event and its XP; badges stay); daily goal bonus 100. Total XP = sum of events + 100 per goal day.
- **Ranks** (`record Rank(Name, From, Color)`): Junior 0 `#607D8B`, Mid 1000 `#2E7D32`, Senior 3000 `#1565C0`, Staff
  7000 `#6A1B9A`, Principal 15000 `#C62828`.
- **Daily goal**: 3 questions (checked or shown) and 1 lesson on the same day; awarded once per day.
- **Streak**: days in a row with any event, counted back from today (or from yesterday while today is empty); also
  the best streak ever.
- **Badges** (`record Badge(Id, Icon, Name, Description)`, emoji icons): First answer (first checked answer), Perfect
  10, Hat-trick (last three checked answers all 10), Century (100 questions), Polyglot (a checked answer in every
  topic except Mix), First lesson, Scholar (25 lessons), Graduate (every lesson of a course done), On fire (5-day
  streak), Unstoppable (14-day streak), Goal getter (goal met on 7 days), Night owl (question after 22:00), Early bird
  (question before 08:00).
- After every event: check the goal, then badges not earned yet, then a rank change; save; raise
  `event Action<IReadOnlyList<string>> Awarded` with the lines to celebrate ("+70 XP", "Daily goal complete! +100 XP",
  "<icon> Badge unlocked: <name>", "Rank up: <rank>!"). `LessonUndone` raises it with no lines.
- **Weak topics asked more**: `TopicWeight(topic)` = 1 for a topic with no checked answers, else `1 + (10 - average
  score) / 5` (up to 3). `QuestionPool` picks the topic by these weights instead of uniformly.
- Calls: `QuestionAnswered(tab, topic, score)` after scoring; `QuestionSeen(tab, topic)` on Show answer;
  `LessonDone(course, index, title, courseFinished)` / `LessonUndone(course, index)` from Mark as done.

## Code rendering (`CodeRenderer`)

`Render(text)` → `FlowDocument` (Segoe UI, left aligned, not justified); `Append(document, text)` for the chat.
- Prose takes the light Markdown Claude writes: `#`-`####` headings (bold, 17 / 15.5 pt); `- ` / `* ` / `• ` bullet and
  `1. ` / `1) ` numbered lines as real WPF `List`s (Disc / Decimal; a line without a marker right after an item
  continues it); inline `**bold**` (may hold inline code), `*italic*` / `_italic_`, `[text](https://...)` and bare
  `https://` URLs as links that open in the browser (trailing punctuation stays text).
- Fenced blocks ```` ```lang ```` → a dark box (`#1E1E1E`, Cascadia Mono / Consolas) coloured like VS Code Dark+:
  keywords `#569CD6`, strings `#CE9178`, comments `#6A9955`, numbers `#B5CEA8`, types (PascalCase) `#4EC9B0`, functions
  (word before `(`) `#DCDCAA`, plain `#D4D4D4`. Token regexes for C-like languages (java, js/ts, c#, kotlin...),
  SQL (case-insensitive keywords, `--` comments) and hash-comment languages (bash, python, yaml...).
- Inline `` `code` `` → code font in `#C7254E`. Everything else plain text.
- ```` ```mermaid ```` blocks are drawn as diagrams (`DiagramRenderer`, native WPF, no packages), in the notebook
  colours, inside a card, scaled down to fit (never up); a block it cannot read stays a code block.
  - `flowchart LR|TD` (also `graph`): nodes `id`, `id[box]`, `id(round)` / `id([stadium])`, `id{decision}` (lime
    diamond), `id[(database)]` (violet cylinder), `id((circle))`; links `-->`, `---`, `-.->` (dashed), `==>` (thick),
    with `|label|` or `-- label -->`; chains `A --> B --> C`; `;`-separated statements; `subgraph`/`style`/`class` lines
    ignored; `<br>` breaks a label. Layout: ranks by the longest path (edges that close a cycle ignored), nodes in a rank
    ordered by their parents, centred; arrows from box edge to box edge, labels on a paper-coloured tag. At most 40 nodes.
  - `sequenceDiagram`: `participant` / `actor` (`as` label), messages `->>`, `-->>` (dashed reply), `->`, `-->`, `-x`,
    self-messages as a loop, `Note over A,B:` / `left of` / `right of` (lime); participant boxes at top and bottom,
    dashed lifelines; columns widen to fit their labels. `autonumber`, `activate`, `loop`/`alt`/`end` lines are left
    out of the picture. At most 10 participants.
- Discussions and lessons are told (`QuestionGenerator.Diagrams`): "When a picture explains it better than words - a
  flow, an architecture, a sequence of calls between services - draw one small diagram as a ```mermaid block, as in a
  good tutorial" (flowchart LR/TD with the node and arrow forms above, or sequenceDiagram), at most 10 nodes, short
  labels, no styling, and none when it adds nothing.
